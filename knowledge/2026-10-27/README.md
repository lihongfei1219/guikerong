# 2026-10-27 产品专业知识补充

依据 2026-10-25 理解审查报告，对36个产品的候选问题逐项区分专业定义、宏观描述、银行内部规则、企业材料与原文缺陷。报告是研究线索，不把原审查建议直接变成新准入要求。

本包共有 **16份产品知识文件，每产品恰好一份**；同一产品的不同主题合并在一份文件内。只导入 `products/` 中的文件，README、覆盖清单和研究记录不注入模型。文件的存在不表示该产品所有疑点已解决；公开定义与尚未取得的产品专属口径在正文中分别说明。

## 当前初筛口径（2026-10-27再次调整）

用户已明确将未写出具体核验标准的概括性条款放开审核。在所提供资料没有具体反例时，这类条款直接按初筛口径通过，不要求额外补件、完整政策、银行评分表或笼统确认函。范围不限于国家政策，还包括地方产业方向、一般法律法规、银行信贷政策与其他条件、宽泛科技客群、经营良好、收入稳定、制度规范、团队稳定、资信良好、创新积分较高等概括描述。

这种通过是应用采用的初筛假设，不能表述为已经完成外部调查、已被银行批准或依法取得认证；也不编造没有实际查到的企业事实。官方来源中的定义仍用于解释具体术语，并不是“法律法规已放宽”的证明。明确的资质、名单、数量、比例、期限、实际主体关系、特定许可、已经通过审批/取得额度等结果仍核验；仅泛称符合线上模型准入而未给标准同样初筛放行。已有具体违规、不符或冲突事实时不忽略。

后端以 `assessment_basis=PRELIMINARY_POLICY` 记录初筛放行，允许概括条款无企业引用，不再因缺少专项证明降为待核验；前端条款显示“初筛通过”，产品显示相应数量。具体要求仍执行引用校验，错误引用不能借初筛标记绕过。历史缺少该字段时沿用有据判断的默认方式，人工覆盖后清除模型初筛标记。

本次验证：原有504项测试及新增40项初筛边界测试通过，专用浏览器标记测试通过。18个真实模型合成用例单次运行均符合预期，包含四个截图条款、经营/治理/科技/定性积分等放行，以及明确资质/数值/审批缺失和已知反例的边界。详见[本次合成用例](../../outputs/preliminary-policy-2026-10-27/policy-smoke.json)；未据此推算真实企业准确率或重写旧评估。

## 明确保留的缺口

- 兴速贷：查到七类名录制度及部分列举，未取得人民银行完整原始清单和兴业产品具体适用版本，不拼凑其余类别。
- 交银桂科贷：“创新积分较高”没有明确阈值，按当前初筛口径放行，不再因未公开分档而补件；不能因此伪造企业官方分数。
- 中行创新积分贷：原文有两个维度分位数均大于20%的明确阈值，仍需对应测算结果，不能用其他产品60分或通用统计算法替代。
- 科技研发贷：提供累计公式、逐年公式及结论不受口径影响时的判断方法；若不同口径会改变是否达到2%，仍需确认。
- 科企订单贷：原始申请条件截断，须补产品原文，不能用知识推测。
- 明确银行认可、已审批结果、已取得额度、指定名单或明确评分阈值仍核验；概括“信贷政策”“授信准入”“线上模型基本准入”“其他条件”已从初筛阻断项中移出，放行也不代表银行已经审批。

## 导入与使用

在仓库根目录执行：

```powershell
uv run --env-file .env python -m app.knowledge_import knowledge/2026-10-27/manifest.json
uv run --env-file .env python -m app.knowledge_import knowledge/2026-10-27/manifest.json --apply
```

默认预览，`--apply` 将整包以一次事务追加为已发布知识。重复导入相同版本不会新增；同包更新会停用旧版本并发布新版。用户手工停用的相同版本不会恢复。不同包标识视为独立来源；不要通过改包标识来更新已有包。

刷新工作台后可在左侧“专业知识”查看。重新匹配时，每个产品只携带自己的知识文件；文件保留来源链接和查证日期，企业事实仍来自企业材料。导入不改企业资料、原始产品CSV、历史匹配或人工复核。对整个产品原文设置范围，是为了让一份文件涵盖多个专业主题；各节的适用条款仍受正文限定。
